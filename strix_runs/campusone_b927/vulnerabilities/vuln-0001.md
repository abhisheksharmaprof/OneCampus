# OAuth callback state is not bound to the initiating user in calendar integration

**ID:** vuln-0001
**Severity:** LOW
**Found:** 2026-08-12 05:57:03 UTC
**Target:** /workspace/CampusOne
**Endpoint:** /api/v1/admin/calendar/oauth/callback
**Method:** GET
**CWE:** CWE-287
**CVSS:** 3.7
**Fix Effort:** Medium

## Description

The calendar OAuth callback accepts any request that presents a live `state` value and provider `code`, then binds the resulting calendar connection to the victim institute without verifying that the callback caller is the same authenticated administrator who initiated the flow. This allows cross-session callback completion and unauthorized provider-account binding if an attacker obtains a live `state` value before it is consumed.

## Evidence

The reviewed callback endpoint is unauthenticated and does not bind the callback caller to the recorded initiating user:

```python
class CalendarOAuthCallbackView(APIView):
    permission_classes = (AllowAny,)
```

```python
state = CalendarOAuthState.objects.filter(
    state=request.query_params.get("state", ""),
    used_at__isnull=True,
).select_related("institute").first()
```

```python
tokens = exchange_code(state.provider, request.query_params["code"])
connection, _ = CalendarIntegrationConnection.objects.update_or_create(
    institute=state.institute,
    provider=state.provider,
    defaults={...},
)
sync_connection(connection)
state.used_at = timezone.now()
state.save(update_fields=("used_at",))
```

The start endpoint records the initiating user but that field is never enforced at callback time:

```python
CalendarOAuthState.objects.create(
    state=state,
    institute=request.institute,
    user=request.user,
    provider=provider,
    expires_at=timezone.now() + timedelta(minutes=10),
)
```

The underlying model explicitly stores both `user` and `institute`, confirming that caller binding was available in the data model but not enforced in the callback logic:

```python
class CalendarOAuthState(models.Model):
    state = models.CharField(max_length=128, unique=True)
    institute = models.ForeignKey("institutes.Institute", on_delete=models.CASCADE)
    user = models.ForeignKey("identity.User", on_delete=models.CASCADE)
    provider = models.CharField(max_length=24, choices=CalendarIntegrationConnection.Provider.choices)
    expires_at = models.DateTimeField()
    used_at = models.DateTimeField(null=True, blank=True)
```

`CalendarIntegrationConnection` is unique per institute and provider, so a successful unauthorized callback changes the victim institute's effective integration binding for that provider.

## Impact

An attacker who learns a valid in-flight calendar OAuth `state` value can complete the callback from a different browser session, including an unauthenticated one, and attach the attacker's Google or Microsoft calendar account to the victim institute's integration context. Because the callback marks `used_at` only after token exchange, connection update, and sync, there is also a replay/race window before the state is finalized.

## Technical Analysis

The OAuth start endpoint records the initiating administrator in `CalendarOAuthState.user` together with the target institute and provider. However, the callback endpoint is explicitly exposed with `AllowAny` and resolves the pending OAuth transaction only by the opaque `state` value and `used_at__isnull=True`.

The callback then exchanges the supplied provider `code` using `state.provider` and persists the resulting connection by `state.institute`, with no authentication check and no comparison between the callback caller and `CalendarOAuthState.user`.

Relevant behavior:

```python
state = CalendarOAuthState.objects.filter(
    state=request.query_params.get("state", ""),
    used_at__isnull=True,
).select_related("institute").first()
```

```python
tokens = exchange_code(state.provider, request.query_params["code"])
```

```python
connection, _ = CalendarIntegrationConnection.objects.update_or_create(
    institute=state.institute,
    provider=state.provider,
    defaults={...},
)
```

The callback never checks `request.user`, `request.auth`, or whether `request.user == state.user`. As a result, possession of a live `state` value is sufficient to authorize the connection finalization. The state is only marked used after exchange, update/create, and sync, which leaves a race window for concurrent completion attempts.

Because `CalendarIntegrationConnection` is unique per `institute` and `provider`, a successful unauthorized callback binds or overwrites that institute/provider integration with attacker-controlled provider credentials.

## Proof of Concept

1. Authenticate as an institute administrator and initiate a calendar OAuth connection for a provider, causing the server to create a `CalendarOAuthState` row containing the victim `user`, `institute`, `provider`, and a live `state` value.
2. Capture the generated `state` value before it is consumed.
3. In a different browser session, or with no authenticated application session at all, send a request to `/api/v1/admin/calendar/oauth/callback` with that same live `state` value and a valid provider authorization `code` for the attacker's provider account.
4. Observe that the callback succeeds even though the callback caller is not the initiating administrator.
5. Confirm that the resulting `CalendarIntegrationConnection` is created or updated for the victim institute and chosen provider.
6. Repeat the callback concurrently before `used_at` is written to observe the replay/race window caused by marking the state as used only after token exchange, update/create, and sync.

```python
import threading
import requests

BASE = "http://127.0.0.1:8000"
STATE = "LIVE_STATE_VALUE"
CODE = "ATTACKER_PROVIDER_AUTH_CODE"

url = f"{BASE}/api/v1/admin/calendar/oauth/callback"
params = {"state": STATE, "code": CODE}


def fire(label):
    response = requests.get(url, params=params, allow_redirects=False, timeout=15)
    print(label, response.status_code, response.headers.get("Location"))

# Unauthenticated cross-session completion
fire("single")

# Optional race demonstration
threads = [threading.Thread(target=fire, args=(f"race-{i}",)) for i in range(2)]
for thread in threads:
    thread.start()
for thread in threads:
    thread.join()
```

## Remediation

1. Require the callback to complete in the same authenticated application session that initiated the OAuth flow, rather than treating possession of the opaque `state` value as sufficient authorization.
2. Compare the authenticated callback principal to `CalendarOAuthState.user` before exchanging the provider `code` or updating any institute connection.
3. Consume the state atomically before token exchange and synchronization so concurrent callbacks cannot reuse the same live state.
4. Fail closed when the callback is unauthenticated, when the authenticated user does not match the recorded initiator, or when the state has already been consumed.
5. Consider binding the state to a signed nonce stored in the user's authenticated session in addition to the database row.

## Assumptions

This finding assumes an attacker can obtain a valid live `state` value before expiry, for example through callback interception, exposed logs, browser history leakage, or another in-scope weakness that discloses the authorization URL. The demonstrated impact is the unauthorized completion and binding of the callback once that state is known.
